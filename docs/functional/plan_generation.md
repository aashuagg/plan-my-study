# Plan Generation — End-to-End Flow

## Overview

A weekly study plan is generated by combining student profile data, current curriculum topics, SM-2 review queue, and learning history into a structured prompt, which is sent to an AI model (Ollama or Claude). The AI returns a JSON schedule for the week.

---

## Data That Feeds Into the Prompt

### 1. Student Profile

```
- Name
- Grade (e.g., "UKG")
- Board (e.g., "CBSE")
- Daily study duration in minutes
- Study days per week (weekly_frequency)
- Subjects list
```

This determines: how many day slots to fill, how many minutes per day, and which subjects are valid.

### 2. Current Curriculum (New Topics)

Pulled from `curriculum_items` for the active newsletter period. Formatted as:
```
- LITERACY: Letter Recognition (starts 2026-05-01)
- NUMERACY: Counting to 20 (starts 2026-05-03)
```

Limited to the first **20 items** to prevent token overflow.

### 3. Topics Due for SM-2 Review

Topics from `learning_history` where `next_review <= today`. Formatted as:
```
- HINDI: Vowels (due: 2026-05-10, 3 days overdue, easiness: 2.3)
```

Limited to the first **15 items** to prevent token overflow.

### 4. Learning History Summary

A per-subject summary of topics that have been reviewed at least once (`last_reviewed IS NOT NULL`):
```
- LITERACY: 8 topics practiced, last session 2026-05-11 (2 days ago)
- HINDI: 5 topics practiced, last session 2026-05-08 (5 days ago)
```

Topics that have never been reviewed are excluded — they are "new" not "overdue".

### 5. Optional Parent Inputs

- **Focus request:** Free text, e.g. "Extra Hindi practice this week"
- **Upcoming events:** Free text, e.g. "Olympiad on May 20"

## SM-2 Scheduling Rules Embedded in the Prompt

The system prompt instructs the AI to:

| Rule | Detail |
|------|--------|
| **Prioritise due topics** | Topics with `next_review <= today` are due and should appear this week |
| **60/40 split** | Approx 60% new curriculum topics, 40% review topics |
| **No subject neglect** | No subject should go unreviewed for more than 7 consecutive days |
| **Subject frequency** | Every subject must appear at least 2 times during the week |
| **Even distribution** | Distribute subjects across the week; avoid consecutive same-subject days |

---

## Hard Constraints

These are enforced via explicit instructions in the user-facing prompt section (`_build_full_prompt`):

### 1. Maximum 2 Topics Per Day (ABSOLUTE)

```
ABSOLUTE HARD LIMIT: Maximum 2 topics per day, no exceptions.
It is CORRECT and EXPECTED to leave topics unscheduled.
Unscheduled topics automatically carry over to next week.
A plan with 2 topics per day is a PERFECT plan.
A plan with 3+ topics on any day is a FAILED plan.
```

### 2. Subject-Topic Matching

Every topic listed for a day must belong to a subject that also appears in that day's subjects list:

```
SUBJECT-TOPIC MATCHING RULE:
Each topic must belong to one of the subjects listed for that day.
Before finalising each day, verify: does every topic's subject appear
in that day's subject list?
```

### 3. No "Catch-Up Day"

```
The last day of the week follows the SAME rules as every other day.
There is no "catch-up" day. If week ends with unscheduled topics,
they move to next week.
```

### 4. No Invented Topics

```
ONLY use subjects and topics from the "Current Curriculum" and
"Topics Due for Review" sections. DO NOT invent, create, or make up
ANY subjects or topics.
```

### 5. Exact Topic Name Copying

```
Copy topic names EXACTLY as they appear in the curriculum data.
```

This is critical: if the AI paraphrases a topic name, it won't match the `learning_history` row, and the session cannot be saved.

## Output Schema

The AI is expected to return JSON matching:

```json
{
  "weekly_plan": [
    {
      "date": "2026-05-19",
      "subjects": ["LITERACY", "NUMERACY"],
      "topics": ["Letter Blending", "Counting to 20"],
      "is_new_topic": [true, false],
      "duration_minutes": 30
    }
  ],
  "rationale": "Hindi was prioritised because it was last practiced 5 days ago..."
}
```

The `JsonOutputParser` (LangChain) appends format instructions to the prompt to enforce this structure.

## How Ollama vs Claude Behave Differently

| Aspect | Ollama (llama3.2) | Claude (sonnet) |
|--------|-------------------|-----------------|
| **2-topic hard limit** | Frequently violated (3–4 topics per day common) | Reliably respected |
| **Subject-topic matching** | Often mismatches topics to wrong subjects | Consistently correct |
| **Topic name fidelity** | Sometimes paraphrases topics | Copies names exactly |
| **JSON format** | Uses `format="json"` mode to force structure; occasionally malformed | Clean JSON consistently |
| **Rationale quality** | Brief and generic | Detailed and specific |
| **Inference speed** | Fast (local, no latency) | Slower (network API call) |
| **Cost** | Free | Paid API |

**Workaround for Ollama violations:** Validate `plan_data` after generation — count topics per day and alert the parent if any day exceeds 2 topics. This validation is not yet implemented in the MVP.

## Known Issues and Workarounds

### Issue 1: Topic Name Mismatch

**Problem:** The AI generates a topic name like "Letter Blending" but the DB has "Blending of Letters". The `topic_lookup` in `weekly_plan.py` uses an exact `"{subject}|{topic}"` key and returns `None`. The topic gets `learning_history_id = None` and cannot be saved.

**Current workaround:** Sessions for unmatched topics are silently skipped with a UI message. The parent can note which topics were skipped.

**Planned fix:** Fuzzy matching on topic lookup; or enforce exact topic names at plan generation time with a stricter prompt.

---

### Issue 2: Ollama Ignoring the 2-Topic Cap

**Problem:** llama3.2 often schedules 3–4 topics per day despite the explicit hard limit instruction.

**Current workaround:** Use Claude (production) for reliable plans. When using Ollama, the plan must be reviewed manually before acting on it.

**Planned fix:** Post-generation validation that trims plans exceeding 2 topics per day and logs a warning.

---

### Issue 3: Token Overflow for Large Curricula

**Problem:** The curriculum formatter limits to 20 items and the due-topics formatter limits to 15 items. Topics beyond these limits are not included in the prompt and may be missed in the plan.

**Current workaround:** Keep the monthly curriculum concise (< 20 usable topics after cleaning).
